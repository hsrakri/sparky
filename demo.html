How it was actually built

The point isn't the sim — it's that the orchestrator handed the whole job to the coder, and we corrected the coder like a teammate.

1

Delegate, don't prompt

The task went to the Hermes agent whose main model is Nemotron-3.5-Lightning (:8001). Nemotron decomposed it and delegated the code to the Qwen3.8-27B coder (:8000) — two NVFP4 models co-located on one GB10.

2

First draft, real bugs

The coder emitted a 32 KB single-file sim — with a missing control-panel and an un-interpolated rgba() template. It ran frozen.

3

Correct it like a teammate

We fed a precise correction back through the orchestrator; the coder edited the file in place and fixed both. Then we calibrated the physics (ablation rate, surface heat capacity so the shell reaches ionization, the re-entry-corridor verdicts) against a headless-browser harness that measured each run.

4

Verified on the metal

Throughput read straight off vLLM's Prometheus /metrics on the Spark — dense-27B decode held its measured baseline while the orchestrator fronted the conversation.

Honest footnote: it took two correction rounds and a physics calibration pass — the first draft looked plausible but was mis-scaled. That loop is the workflow this repo is about.
