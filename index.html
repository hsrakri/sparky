RECIPE / 01

Co‑locating 2×30B on one GB10

vLLM treats --gpu-memory-utilization as a per‑process reservation that must fit in free memory — so “0.45 + 0.45” doesn’t partition, it races. The recipe: fractions summing ≲ 0.88, sequential startup (coder first), enforce‑eager for the hybrid Mamba‑MoE, and a boot script that makes reboots deterministic.

RECIPE / 02

Qwen3.8‑27B dense — beating the bandwidth roofline

A dense 27B streams all ~14 GB of active weights per token: 273 GB/s ÷ 14 GB ≈ a hard ~20 tok/s ceiling. n‑gram speculative decoding (no draft model) hit 22.1 tok/s — 1.9× — but broke qwen3_coder tool parsing, so the agent config trades it back. The recipe shows both paths, with acceptance stats.

Field guide

Four ways it crashed
before it worked.

Every one reproduced, root‑caused, and fixed. Tap to expand.

CRASH Both models started together FIXED›
Launching two vLLM instances simultaneously at 0.45 + 0.45 races the memory profiler — whoever profiles second sees the other’s memory as used: ValueError: No available memory for the cache blocks.
Fix: start sequentially — coder up, wait for /v1/models 200, then orchestrator.
CRASH “Just give the 2nd model 0.9” FIXED›
Utilization is a share of total that must fit in free memory: Free memory on device (54.22/121.69 GiB) on startup is less than desired GPU memory utilization (0.9, 109.52 GiB).
Fix: size to free memory → 0.42 for the second model. Sum ≲ 0.88.
CRASH Mamba cache “align” mode FIXED›
NVIDIA’s recipe flag forces an oversized attention block: AssertionError: In Mamba cache align mode, block_size (4176) must be <= max_num_batched_tokens (2048).
Fix: drop --mamba-cache-mode align (or raise --max-num-batched-tokens ≥ 4176).
HANG Silent freeze before weight load FIXED›
Co‑located, Nemotron’s torch.compile / CUDA‑graph capture deadlocks at boot — banner prints, memory stays flat, nothing ever loads.
Fix: --enforce-eager. Costs decode speed; boots every time.
Single‑stream decode

MoE sprints.
Dense grinds. Physics.

Decode is memory‑bandwidth‑bound: tok/s tracks active bytes per token, not total parameters. A 3B‑active MoE flies; a dense 27B pays for every parameter, every token.
